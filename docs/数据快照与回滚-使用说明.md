# 数据快照与回滚 —— 使用说明（2026-10-06）

给「大批导入」（如杭州十几万条）留退路用。**导入前先拍快照，出事按快照还原。**

> ⚠️ 先记住一句话：**这套东西只管云端数据库**。项目那三层备份（本地 / GitHub / 腾讯云）备的是**代码**，不含数据。

## 二、导入杭州之前，先做这两个检查

### 1. ⭐ 查「客户编号」有没有跟金华重号（最重要！）

订单是**按客户编号**（`orders.customerCode`）挂到客户身上的。如果杭州的编号跟金华重了，**订单会串到错的客户头上**，这比"多了一堆客户"难查得多。

导入前拿杭州表的编号列，跟数据库里现有的比一下有没有交集。

### 2. 确认杭州表里有「城市」列

导入链路（`import_excel.py`）靠表里的 **城市 / 行政区 / regionName** 推三层骨架（城市/区域/商圈）。
**没有城市列 → 杭州那批会被推到错的区域，或者全落 "❓ 未划分商圈"。**

## 三、万出问题了：怎么回滚

**所有命令都在项目根目录（`D:\WFR\visit-miniapp`）下开 Git Bash 跑。**

### 第 1 步：先看看到底多了/改了什么（**只读，不写任何东西**）

```bash
node admin/tools/restore_snapshot.js --in "_scratch/snapshot-20261006-124014"
```

它会逐集合列出：

- **🆕 新增** = 云端有、快照没有的 → **这些就是导入进来的**（还会按城市分组，一眼看出是不是杭州那批）
- **✏️ 被改** = 两边都有但内容不一样 → 被覆盖了
- **❓ 缺失** = 快照有、云端没有 → 被删了（少见）

### 第 2 步：确认"新增的确实该删"之后，选一种处置

| 想干什么 | 命令 | 说明 |
|---|---|---|
| **保守**（可恢复） | `--soft-delete-new` | 新增客户**进回收站**，在「🏪 客户管理 → 🗑 回收站」随时能恢复 |
| **彻底**（不可逆） | `--hard-delete-new` | 真删新增客户，并连带删它们的**订单 / 明细 / 批次成员** |
| **改回原样** | `--restore-changed` | 把**被覆盖**的客户恢复成快照里的内容 |

例如保守清掉：

```bash
node admin/tools/restore_snapshot.js --in "_scratch/snapshot-20261006-124014" --soft-delete-new
```

只想处理客户、不动订单：

```bash
node admin/tools/restore_snapshot.js --in "_scratch/snapshot-20261006-124014" --soft-delete-new --only customers
```

### 第 3 步：复查

把第 1 步那条命令**再跑一遍** —— 新增应该变成 0。

## 四、几个必须知道的注意事项

1. **`--hard-delete-new` 是不可逆的**。想保守就用 `--soft-delete-new`（进回收站），效果上"列表、地图、筛选里都消失"，只是数据还留在库里。
2. **本脚本不碰云存储**（业务员拍的照片 / 录音）—— 真要连照片一起清，需要另外处理，跟我说。
3. **也不清这些**：`coord_fix_requests` / `customer_remarks` / `transcripts` / 任务里的 `customerIds`、`dayPlan` 引用。
4. **大快照吃内存**，客户十几万条时若报内存不足，改成：
   ```bash
   node --max-old-space-size=4096 admin/tools/restore_snapshot.js --in "<快照目录>"
   ```
5. **默认永远是"只预览"** —— 不加开关绝不会写一个字节。

## 五、想再拍一次新快照（换一个时间点）

```bash
node admin/tools/export_snapshot.js
```

默认会新建 `_scratch/snapshot-<时间戳>/`，不会覆盖旧的那份。
也可以指定目录或只导某一个集合：

```bash
node admin/tools/export_snapshot.js --out "D:\bak\hz-before"
node admin/tools/export_snapshot.js --only customers
```

跑一次大约 **2 分钟**（customers 70 页 / 约 84 秒）。
