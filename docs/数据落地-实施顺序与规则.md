### 4.1 数据模型
1. **只有一套 `customers` 集合**，不搞旁路集合（老板多次强调）
2. **同一个客户编号 = 同一家店**（老板/老板娘各自注册）：视作一家，**购买次数多的为主**，主档挂 `subAccounts[]`、副档打 `mainAccountId` + `isSubAccount:true`；**订单两家全要**；本批 3 组（c53 / c155 / c412）
3. **信息全进，不做聚合** —— 平台 45 列原样收进 `plat` 子对象
4. **坐标分层取数**：有商城坐标→用商城（本批 463 家全部如此，实地验证过）；没有→回落平台坐标；并把来源写进 `coordSource`
5. 点评侧重复记录 → 方案 A 字段级合并（信息更丰富 > 评分更高 > 随机；**收录时间取更早**）

### 4.2 字段标准化
| 项 | 规则 |
|---|---|
| 日期（商城侧） | `2026-03-28 17:14:30.497000` → 存 `2026-03-28`（去掉微秒与时分秒） |
| 日期（订单） | Excel 序列号（`46273.529…`）→ 转真实日期 |
| 电话/金额 | 数字列读出来是 `float` → 转字符串并去掉 `.0`；金额转数字 |
| 多电话 | 拆 `phone`（主）+ `phone2`（备） |
| 坐标 | **存储保持 `lng`/`lat` 两字段**（顺序不动）；**显示一律纬度在前** |
| 空值 | 点评侧 `phone1` 常是 `-` → 视为空，不能假设有值 |
| 业务负责人 | **原值照抄**（`快餐盒c聚火配送🔥` 这种就是原值，不要"像不像人名"地改） |

### 4.3 导入规则
1. **按字节分片**：累加 `Buffer.byteLength` 到 **60~70 KB** 切一片（云函数入参上限 100 KB；实测 customers 平均 2371 B / 最大 6200 B）
2. **幂等**：重复导入 = 更新，不是新增（键见阶段 2）
3. **断点续跑**：前端记住 `nextIndex`，失败/刷新后从断点继续
4. **先校验后写**：单批里有非法行先剔除并记入报告，不要写半截
5. **只增不删**：导入不清库；清库走专门的 `wipeData` / `purgeUnbatchedCustomers`
6. 每片写入后再回查条数，不一致立即停

### 4.4 工程纪律（项目既有，重申）
- 云函数每改必 `node --check`；`admin.html` 必须保留 **CRLF + 那 16 个裸 LF**（改前数一遍、改完再数一遍）
- 每次改动后**语法检查 + 行尾核对**（行尾判定用字节级方法，别用 `grep`）
- **版本号 bump 必须先经老板点头**（后台 `APP_VERSION` 是文员端「检查更新」的判据）
- 临时文件放 `_scratch/`，**不主动清理**
