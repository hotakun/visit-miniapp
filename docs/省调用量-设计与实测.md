### ② 给云端"要提醒的写操作"补「变化时间戳」（✅ 已做）

**为什么**：现在后台只能"定时问"，因为它**不知道有没有变化** → 大量白问。
**做法**：云端加一个**全局时间戳**（`settings.pollDirtyAt`，任何"要提醒的"写操作都更新它）：

| 哪类写操作 | 现在写了吗 |
|---|---|
| 业务员提交拜访（含审核）| ❌ 要补 |
| 手机端「📍 坐标报错」 | ❌ 要补 |
| 新用户注册 | ❌ 要补 |
| 手机端「加新店」 | ✅ 已有（`custDirtyAt`）|

### ③ 后台改成「先问服务器、只有变了才叫云端」

**现在的 `pollAll`**：每 30 秒无脑叫一次云端 ❌ → **2,880 次/天/客户端**
**改后**：
```
后台 ──每30秒──> 你的服务器：pollDirtyAt 变了吗？
                        ├── 没变 → 什么都不做（0 次云端）✅
                        └── 变了 → 叫一次 pollAll（这时候才花钱）
```
**效果**：半夜没人用 → **0 次**；白天只有真有事才叫 → **几十 ~ 几百次/天**。

### ④ 服务器「被动通知」（**建议暂缓**）

**想法**：云端一有写操作就通知服务器"我变了，你来拉" → 服务器不用定时轮询。
**收益**：服务器 → 云端 1,440 → 几十次/天。
**为什么暂缓**：
- ⚠️ 要动服务器（加 `/notify` 接口 + 改 `pgsync` 为"被动 + 10 分钟兜底"）
- ⚠️ 通知会丢（服务器挂了 / 网络抖）→ 必须有兜底，逻辑复杂
- ⚠️ 收益只有 ~1,400/天（相比 ②③ 的 2,880 小）
**建议**：**先做 ②③，明天看数据再定**。

## 五、架构原则（这场改造的总结）

1. **云端只做两件事**：**收写**（唯一真相源）+ **报变**（时间戳）
2. **你自己的服务器管**：**存全量 + 供读**（后台/地图/列表全走它）
3. **手机端不直连服务器**（要 https + 备案域名，成本大）→ 写走云端
4. **"看数据先读本地/服务器"** —— 只有"变了"才回头叫云端
5. **不确定的钱不花**：任何"要花钱的操作"（导入 / 批量改 / 全量拉）**先说清花费再动**
