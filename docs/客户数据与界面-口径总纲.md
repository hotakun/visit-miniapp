## 三、合并与配对规则（老板已拍板）

1. **配对键 = `shopuuid`**（商城表第 49 列 ↔ 点评表 shopuuid）→ 硬匹配 **462/463（99.8%）**；剩 1 条点评记录靠**电话 + 地址**兜底认领（c53 的 `红太阳川菜馆`）。
2. **同编号 = 同一家店**（老板/老板娘各自注册）：**购买次数多者为主**，少的为副；详情页以主家为主，**主+副的订单全要**；**主副字段级合并**（哪家完整用哪家）。
3. **点评侧重复 = 方案 A 字段级合并**：先按 ①有效字段数多 → ②评分高 → ③随机 定主记录；再逐字段补缺；**收录时间取更早**。（实测 3 组：c53 / c155 / c412）
4. **坐标（本批）一律用商城侧**；点评坐标入库留底不使用。**以后**导入未匹配商城的客户才回退用点评坐标。
5. **信息全进、不聚合**：源表每一列都要有归处；订单/明细全量入库。
6. **导入后不建批次** → 客户落在「未分批」，**由老板自己筛选分批**。
7. **导入时必须滤掉**：`配套设施` 列里混着的 `收录4年` / `收录5年` / `收录9年`（那是收录时间，不是设施）。

**两类空态**（必须一眼分得清）：
- **能录入** = 橙色 ＋（招牌菜 `.empty3`+`.addtap`；设施用行尾小 ＋ `.plusbar`）
- **客观缺失** = 淡灰 `.empty4`（虚线框 + 灰图标 45% + 主文案 + 小字提示）—— 商城信息/订单/评分/备注/历史

## 八、踩过的坑（本数据/界面相关）

1. **导入脚本必须用真正的 CSV 解析** —— 支付方式字段形如 `"现结,现金交易"`（带逗号引号）
2. **日期是 Excel 序列号** —— `46258.44` = 2026-08-24；表格里的日期列要先判是不是纯数字
3. **商品规格写法不统一** —— `透明*300套` / `透明×300套`（还夹零宽字符）→ 聚合前归一化
4. **点评表「收录时间」有的是文本「预估在2025-06到2026-04之间」** —— 转换函数要能吃下非数字
5. **同编号重复不是脏数据** —— c53/c155/c412 是老板+老板娘各自注册，**别当重复删掉**
6. **`edit_file` 有读证据校验** —— 改文件前必须先用 `read_file` 覆盖到目标行，**且只认最近一次的读窗口**（读完别处再改就会失效）
7. **`bash` 会改文件时必须能声明改了哪些文件** —— 且那些文件要有读证据；跑 Python 脚本改文件容易被拦，改用 `write_file` 写新脚本名可绕过
8. **WXML 只用 view/text** —— 禁任何 HTML 标签（div/br 曾致白屏）
9. **不用 `window.confirm`/`prompt`** —— 一律页内弹层
