## 一、这是个什么页

业务员点开一家客户 → 一个页面看全：「这家什么情况 / 买过什么 / 到了店里该聊什么 / 该拍什么照」。
一屏从上到下：**店名卡 → 若干信息卡 → 底部「开始拜访」**。

演示稿里有 **4 个样本**，覆盖真实世界的四种情况（切换按钮在最上面）：

| 样本 | 客户 | 情况 |
|---|---|---|
| **A** | 胡记牛骨头(永康东塔店) | 已入商城 · 有订单 · 平台信息齐全 · 有备注有历史 |
| **B** | 老婆大人(永康金城店) | 未入商城 · 平台查得到 · 但没评分 |
| **C** | 太和牛肉板面(杭州店) | 未入商城 · 有**平台真门头照**（演示稿里能看到：落在「🏪 商城信息」卡的三格里，见 §六） |
| **D** | 冒菜西施(皇城北路店) | 已入商城 · 有订单 · **平台完全没收录这家** |

**铁律（2026-09-13 老板定，语气更硬）**：这 6 张卡 —— 🏪 商城信息 / 📦 购买记录 / 📊 平台口碑 / 🛎 服务与设施 / 📝 管理员备注 / 🕑 拜访历史 —— **永远出现**，只是"里面有没有内容"不同；**任何一张都不会因为没数据就整卡消失**。业务员要靠它们现场录信息、也要靠它们判断"这家缺什么"。

## 三、老板拍板的口径（改之前先看这里，别再翻案）

### 1. 店名卡

- **「已入商城 / 未入商城」胶囊不显示**（老板明确要求去掉）。
- 商城状态改用**卡片辉光颜色**表达：已入商城 = **淡橙**一圈；未入商城 = **天蓝**一圈。
  判定用 `.head.is-mall` / `.head.is-new` 这类 class，**不要再靠 `:has(.tag)`**。
- 店名右边最多两个小胶囊：
  - **新店** → 蓝胶囊 `#EAF2FE`/`#1F63C4`
  - **收录 N 年**（平台收录 ≥3 年才显示）→ 淡红胶囊 `#FDECEC`/`#C0392B`，**要小、要精致、不要粗体**
    （定稿值：`font-size:10px; font-weight:500; padding:2px 7px`）
- **「报错」方块在电话行右侧**（不是地址行）：44×44 方块、淡蓝底、📍 图标 + 「报错」两字、占两行。
  - ⚠️ 这里反复改过：地址行 → 营业时间行 → 又回电话行。**相机按钮已彻底取消**（CSS/JS/渲染全清），位置让给报错。
  - 状态 class `.mline.hasfix` 是给"地址行带方块"那版用的 —— **2026-09-13 已从演示稿删掉**（连带 `.posfix` / `.shot` / `.shots` / `.footer .b1` / `.tag.mall` / `.tag.nomall` 一批没人引用的死样式一起清）。

### 2. 签约业务员（重要，我之前犯过错）

- **取值 = 客户表 `客户列表-含经纬度.csv` 的「业务负责人」列原值**，值是什么就填什么。
- 胡记牛骨头(c39) 和 冒菜西施(c585) 的原值都是 **`快餐盒c聚火配送🔥`** —— 看着像配送组名，**但那就是这个字段的口径，不要用"像不像人名"去质疑、不要改成业务员真实姓名**。
- 拜访历史里的「拜访人」也跟这个字段保持一致。
- ❌ **不要写「范宇琨」** —— 那是开发者本人（13067737286）的测试账号。

### 3. 门店照片

- 照片**不是独立卡**，挂在 **🏪 商城信息卡下面**的一个 `📷 门店照片` 分区里。
  - ✅ **2026-09-13 已解决**：老板定了「**6 张卡固定出现**」→「🏪 商城信息」卡永远在，**未入商城的客户也有三格**（平台图 / 现场拍），不必单独加卡、也不必双挂。
  - 取图口径（平台图 / 现场拍的优先级）见 **§3.7**。
- **三个相框**（`.shot3`，高 80px、三等分）：
  - 有照片 → 显示照片，点了看大图
  - 空框 → 虚线框 + 📷 + 「拍照」，**点一下就地拍**（`.shot3.empty[data-shot]`）
- 演示稿里拍照塞的是 C 样本那张平台真门头照（`SHOT_DEMO`）。

### 4. 平台口碑 / 服务与设施

- **招牌菜**并进 **📊 平台口碑**卡下方（`.subsec` 细分隔线 + 小标题）。
- **商圈与位置**并进 **🛎 服务与设施**卡下方。
- 卡片内部的录入用 `data-kind`（`dish` / `fac` / `region`）精确定位 ＋ 号，**不要再靠卡片 id**（卡合并后 id 会变，＋ 号会删不掉）。
- **标题栏小胶囊（团购 / 外卖）**：**哪个「有」就显示哪个**，两个都没有 → 标题栏右侧**什么都不显示**（老板 2026-09-13 定，减轻标题栏重量）；小胶囊只显示不可点，可点的是卡内的大标签。
- **设施的录入 ＋ 在「团购/外卖」大标签那一行的最右边**（老板 2026-09-13 二次修正：**不是**标题栏）：内容区**没值就不显示设施那一行**（不留占位），录入用同行行尾的小 ＋（`.plusbar`，在 `.kvrow` 里靠 `margin-left:auto` 贴右）。**招牌菜**仍用带虚线框的橙色 ＋（`.empty3` + `.addtap`）。
- **商圈不做手工录入**（老板 2026-09-13）：平台里没有商圈的 → **「商圈」这一行整个不显示**（不给 ＋、也不写「未标注」）。理由：平台没收录的信息**我们自己不去补录**，以后导入平台数据自然就有。（`ADD.region` 配置留着备用，但页面上暂时没有入口。）
- **「平台地址」「平台图片」「点评页」三行都不显示**（老板 2026-09-13 定）：`d.platAddr` / `d.pics` / `d.url` 字段仍入库，只是详情页不展示。这样「📍 商圈与位置」里只剩：**地址**（永远有）+ **商圈**（平台有才显示）+ **🗺 地图**。

### 5. 管理员备注（可多条）

- 数据结构：`remarks: [{d:'09-05', t:'内容'}, …]`（**不是单条 `remark` 字符串**）。
- 显示：**前面日期、后面内容**，一条一行。
- **日期不带年份**（`09-05` 而不是 `2026-09-05`）。
- **样式要朴素**：日期就是一行**浅灰小字**（`#A6AEBC`、11px、不加粗、无色块无边框）；
  条与条之间一条**淡灰细实线**。❌ 不要做成橙色胶囊（做过，老板说复杂）。
- 卡片标题右边自动显示「N 条」。

### 6. 默认展开规则

按内容决定（`render()` 结尾那段 `openMap`）：

1. 有备注**或**有拜访历史 → 只展开这两张
2. 都没有、但有商城资料 → 展开「商城信息」
3. 都没有（新客）→ 全部收起

### 7. 门头照 / 门店照片的取图口径（2026-09-13 拍板：两者都要）

- **平台图打底 + 业务员现场拍覆盖**（现场拍的那张优先，更清晰、更准）。
- 平台图只取 **`poipicadd` 域名**的「店铺主图」；`bdb`＝平台"美食"占位图、`wmproduct`＝外卖菜品图 → **都要排除**。
- 平台图是美团 CDN 外链 → **导入时转存到自己的云存储**（小程序 `<image>` 直接加载外链要面对防盗链/域名策略，别赌）。
- 本批（金华-永康 463 家）**没有平台图**（永康表连「店铺主图」这一列都没有）→ 三格全空，等业务员现场拍；
  杭州等有图的批次（约 26% 有真门头照）以后导入时自动填进第一格。

### 8. 空态口径：两类空态，一眼分得清（2026-09-13 老板定）

6 张卡固定出现之后，"没数据"就成了常态 —— 所以空态必须**一眼能分辨**：

| 类型 | 哪些内容 | 长什么样 | 为什么 |
|---|---|---|---|
| **能录入（带框）** | 🍜 招牌菜 | **橙色 ＋ 圆形按钮**（`.empty3` + `.addtap`，虚线框内居中）→ 点了弹录入框，填完变成卡片内容 | 业务员到店问一句就能补上 |
| **能录入（在标签行尾）** | 🛎 设施 | 内容区**不留占位**（没值不显示）；录入用**「团购/外卖」那一行最右边的小 ＋**（`.plusbar`）→ 点了弹同一录入框 | 老板 2026-09-13：设施这样最省地方，内容区干干净净 |
| **不补录（没有就不显示）** | 📍 商圈 | **这一行整个不显示**（不给 ＋，也不写「未标注」） | 平台没收录的不由我们补录，以后导入平台数据自然就有（老板 2026-09-13） |
| **客观数据缺失** | 🏪 商城信息 / 📦 订单 / 📊 评分 / 📝 备注 / 🕑 历史 | **淡灰空态** `.empty4`：虚线框 + 灰图标（45% 透明）+ 一句主文案 + 一行更小的提示 | 这些是系统/平台里的客观事实，业务员**录不了**，标 ＋ 号会误导 |

**各卡空态文案（演示稿现行版，老板可改）**：

| 卡 | 标题右侧小字 | 主文案 | 小字提示 |
|---|---|---|---|
| 🏪 商城信息 | `未加入商城` | 这家还没加入商城 | 到店可以推动加入（拜访结果里选「加入商城」） |
| 📦 购买记录 | `暂无订单` | 还没有下过单 | 我们这边没有这家的下单记录 —— 到店先聊供货 |
| 📊 平台口碑 | `平台未收录` | 平台没有收录这家的评分 | 到店主要聊供货和推广，别把"没评分"当缺点 |
| 📝 管理员备注 | `暂无` | 还没有备注 | 管理员在后台加备注，这里就能看到 |
| 🕑 拜访历史 | `暂无` | 暂无拜访记录 | 第一次上门后，这里会留下记录 |

> 门头照（门店照片三格）不适用空态：空框本身就是入口（虚线框 + 📷 + 「拍照」）。

### 9. 「📍 商圈与位置」里的小地图（2026-09-13 老板定，待真机落地）

- **中心点 = 客户坐标**（`lng` / `lat`），**不是**业务员实时定位 → 不需要定位权限、不开 GPS、不弹权限框。
- **不可拖动**：`enable-scroll="{{false}}"`（顺带避免地图抢页面滚动）。
- **可双指缩放、范围 10~20 级**：`enable-zoom="{{true}}"` + `min-scale="10"` + `max-scale="20"`；初始 `scale="16"`（街道级）。
- `show-location="{{false}}"`；`enable-rotate` / `enable-overlooking` 都 `false`；带一个打客户坐标的 pin。
- **尺寸（2026-09-13 定）**：高 **150px（≈300rpx）**、圆角 **12px**、宽占满卡片内容区 —— 老板说"不需要太大"。
- **资源**：小程序 `<map>` 是原生组件，**不用申请腾讯地图 key**；不拖不动的静态图基本不耗流量/CPU。铁规矩：**一个页面只放一个 map**。
- ⚠️ **两个必须真机确认的坑**：① 在**可折叠卡片**里要用 `wx:if` 控制显隐（不能用 CSS 隐藏），否则折叠后可能盖住其它卡片；② `min-scale` / `max-scale` 在个别基础库版本上表现不一致。
- **无坐标客户**：本批 463 家都有商城坐标；"以后导入未匹配的客户"属于**后一期工作**，**本期不处理**（老板 2026-09-13）。

### 10. 平台画像里另外 4 个字段的展示口径（2026-09-13 老板定）

|---|---|---|---|

| **外国** | **暂不展示**（老板 2026-09-13 定） | 字段仍**入库**（信息全进），页面不显示；将来要展示再加 | 463 家**全是 False**（本批没有异国餐厅） |

### 11. 购买记录卡的排版（2026-09-13 老板定）

- **「最近一单」的分割虚线在它上面**（`border-top:1px dashed`）—— 用来把「常买（次数）」和「最近一单」分开（原来那条线挂在「最近一单」下面）。
- **「常买（次数）」字号 = 13.5px**，和「最近一单」一致（原来 12px 偏小）。

### 12. 「连锁情况」单店时不显示（2026-09-13 老板定）

📊 平台口碑里原本有一项 `连锁情况`（示例值 `单店（0 家连锁登记）`）—— **是单店就不显示这一项**。

- **真机判据**：用平台字段 **`连锁店数量`（chainCount）** —— 为 `0` 或空**不显示**这一项；`≥1` 才显示（如 `12 家连锁`）。
- **演示稿**里用文案判断演示：值里含「单店」或「0 家」→ 跳过该行。
- 理由：单店是**绝大多数**（本批几乎全是单店），写出来只是噪音。
- ⚠️ **演示稿里那块地图是「示意块」，不是真地图**：`_scratch/客户详情页-演示.html` 用 CSS 画了个假地图（路网背景 + 中心 📍 + 右下 ＋/− + 右上「示意」角标），**只为先看占位大小与观感**。真机是微信 `<map>` 原生组件 —— 每家店周边路网都不一样，也**没有**那个「示意」角标。
