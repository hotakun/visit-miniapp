# 数据回滚手册（出事时照着做）★ 独立文档，不用翻别的

> 适用场景：**杭州（或任何）大批导入之后发现不对**，要把它清掉 / 改回原样。
> 全部命令在项目根目录 `D:\WFR\visit-miniapp` 下用 **Git Bash** 跑。
> 写完时间：2026-10-06。（配套工具：`admin/tools/restore_snapshot.js`）

## 0. 先花 30 秒判断：该回滚到什么程度？

| 现象 | 该做什么 |
|---|---|
| 多了一堆客户/订单，金华原有数据没被动 | **只删新增** → 第 3 步选 ①② |
| 有些**金华客户被杭州数据覆盖/改了** | 还要 **`--restore-changed`** 改回原样 → 第 3 步选 ③ |
| 只想"先让它从界面消失"，不急着真删 | 用 **`--soft-delete-new`**（进回收站，随时能恢复） |

## 2. 第一步：只读比对（**不写任何东西**，随便跑）

```bash
node admin/tools/restore_snapshot.js --in "_scratch/snapshot-20261006-124014"
```

约 2 分钟（要把云端重新拉一遍）。输出长这样：

```
▶ customers   快照 69737 ｜ 云端 82000
   🆕 新增 12263 条   ← 这些是导入进来的
      按城市：杭州市 12000 ｜ 金华市 263
        · 某某店  码=h1234  杭州市
        · ...
   ✏️  被改 12 条
        · 某某店  id=xxxx
   ❓ 缺失 0 条（快照有、云端没有）
```

**怎么读：**

- **🆕 新增** = 云端有、快照没有 → **就是这次导入进来的**。"按城市"那行帮你确认是不是杭州那批。
- **✏️ 被改** = 两边都有但内容不一样 → 被覆盖了（要恢复）。
- **❓ 缺失** = 快照有、云端没有 → 被删了（少见；若不为 0 要留意）。
- **快照 N ｜ 云端 M** 两个数都要非 0 才正常。

## 3. 第二步：确认后再动手（**三个开关，按需选**）

| 想要 | 命令 | 后果 |
|---|---|---|
| ① **保守**（可恢复） | `--soft-delete-new` | 新增客户**进回收站**：列表、地图、筛选里全消失，随时能恢复 |
| ② **彻底**（不可逆） | `--hard-delete-new` | **真删**新增客户，并连带删它们的**订单 / 订单明细 / 批次成员** |
| ③ **改回原样** | `--restore-changed` | 把**被覆盖**的客户恢复成快照里的内容 |

**常用组合：**

```bash
# 保守：只让杭州那批从界面消失（推荐先这样做，看两天再说）
node admin/tools/restore_snapshot.js --in "_scratch/snapshot-20261006-124014" --soft-delete-new

# 彻底：真删杭州那批（不可逆）
node admin/tools/restore_snapshot.js --in "_scratch/snapshot-20261006-124014" --hard-delete-new

# 有金华客户被改了 → 恢复它们
node admin/tools/restore_snapshot.js --in "_scratch/snapshot-20261006-124014" --restore-changed

# 只想处理客户，不动订单
node admin/tools/restore_snapshot.js --in "_scratch/snapshot-20261006-124014" --soft-delete-new --only customers
```

⚠️ **不加任何开关 = 只预览**，绝不会写一个字节。这是刻意设计的。

## 4. 第三步：复查

把第 2 步那条命令**再跑一遍**。期望：新增变成 0。

如果用的是 `--soft-delete-new`，也可以直接去后台看：「🏪 客户管理 → 🗑 回收站」里应该能看到那批客户，点「恢复」能还原。

---

## 5. 必须知道的 4 件事

1. **`--hard-delete-new` 不可逆**。拿不准就用 `--soft-delete-new`。
2. **本工具不碰云存储**（业务员拍的照片、录音）。真要连照片一起清，得另外处理 —— 跟 AI 说"连云存储照片一起清"。
3. **也不清这些**：坐标报错 `coord_fix_requests`、客户备注 `customer_remarks`、转写 `transcripts`、任务里的 `customerIds` / `dayPlan` 引用。需要一起清就说出来。
4. **内存**：客户到十几万条时若报内存不足，命令前面加一段：
   ```bash
   node --max-old-space-size=4096 admin/tools/restore_snapshot.js --in "<快照目录>"
   ```
