## 一、页面定位与结构

业务员点开一家客户 → **一屏看全**："这家什么情况 / 买过什么 / 该聊什么 / 该拍什么照"。

```
┌─────────────────────────────┐
│ 店名卡（不折叠）             │  ← 店名 / 地址 / 营业时间 / 电话 / 📍报错
├─────────────────────────────┤
│ 🏪 商城信息                  │  ┐
│ 📦 购买记录                  │  │
│ 📊 平台口碑                  │  │  这 6 张卡【永远出现】
│ 🛎 服务与设施                │  │  只是"里面有没有数据"不同
│ 📝 管理员备注                │  │
│ 🕑 拜访历史                  │  ┘
├─────────────────────────────┤
│        【开始拜访】           │  ← 底部固定，只这一个按钮
└─────────────────────────────┘
```

**铁律（老板 2026-09-13 拍板）**：上面 6 张卡是**固定骨架**，任何一张都**不会因为没数据就整卡消失** —— 没数据时给"空态"。
业务员要靠它们现场录信息，也要靠它们一眼看出"这家缺什么"。

| 1 | 商城信息 | 🏪 | `最近购买 <日期>` → 没有则 `最近浏览 <日期>` → 再没有 `注册 <日期>` | `未加入商城` | 商城导出（我们自己的系统） |
| 2 | 购买记录 | 📦 | `累计 N 单 · ¥金额` | `暂无订单` | 订单表 + 订单明细 |

### 0. 店名卡（不折叠，永远显示）

- **店名 + 最多两个小胶囊**：`新店`（蓝 `#EAF2FE`/`#1F63C4`）、`收录 N 年`（淡红 `#FDECEC`/`#C0392B`，**平台收录 ≥3 年才显示**，要小：`font-size:10px; font-weight:500; padding:2px 7px`）。
- **不显示「已入商城 / 未入商城」胶囊**（老板明确去掉）→ 商城状态改用**卡片辉光颜色**：
  - 已入商城 = **淡橙**一圈（`.head.is-mall`）
  - 未入商城 = **天蓝**一圈（`.head.is-new`）
- **📍 报错方块在电话行右侧**（反复改过：地址行→营业时间行→回电话行，最终定电话行右侧）：44×44、淡蓝底、📍 + 「报错」两字占两行。**相机按钮已彻底取消**。
- 缺失时的降级文案：营业时间缺 → `未收录营业时间`（2026-09-13 老板定：不要后面那句"出发前先电话确认"）；电话缺 → `平台未收录电话`（圆形电话图标变灰）。
- **营业时间下面还有一行「品类」**（2026-09-13 新增）：🏷 `大/中/小类` —— **去重后**用 ` · ` 拼（`美食` + `东北菜` + `东北菜` → `美食 · 东北菜`）；**这一行右侧还放榜单**（金色小字 🏆，10.5px，超长省略）；两者都空则不出这一行。

### 1. 🏪 商城信息

- **内容**：注册商城时间 / 签约业务员 / 最近下单 / 最近浏览商城。
- **签约业务员口径（老板特别交代过）**：取客户表「**业务负责人**」列的**原值** —— 值是什么填什么（可能是 `快餐盒c聚火配送🔥` 这种组名，**不要**改成真人姓名，**不要**写「范宇琨」）。
- 卡内下方固定有 **📷 门店照片** 分区（三个相框，见 §四）。
- **空态**（未入商城）：淡灰空态「这家还没加入商城」+ 小字「到店可以推动加入（拜访结果里选「加入商城」）」；**三个相框照常在**（可现场拍）。

### 2. 📦 购买记录

- **卡内只放摘要**：最近下单 / 常买（次数，可展开，折叠时右侧显示前 2 个）/ 最近一单 / 💡 补货提示。
  - 排版（2026-09-13 定）：**「最近一单」的分割虚线在它上面**（把「常买（次数）」与「最近一单」分开）；**「常买（次数）」字号 13.5px**，与「最近一单」一致。
- **「查看全部 N 单」** → 全屏抽屉看完整流水，每单点一下展开明细（日期 / 商品 / 规格 / 箱数 / 金额）。
- **空态**：淡灰空态「还没有下过单」+ 小字「我们这边没有这家的下单记录 —— 到店先聊供货」。
- 注意：商城里的「购买次数」**不等于**实际订单数（c402 商城记 140 次、明细只有 19 单）—— **两个数字都要保留、分开展示**。

### 3. 📊 平台口碑（含 🍜 招牌菜）

- 评分大数字 + 分项条（口味/环境/服务）+ 人均 / 评论总数 / 连锁情况。
- 卡内下方分区 **🍜 招牌菜**（平台菜品标签）。
- **空态**：淡灰空态「平台没有收录这家的评分」+ 小字「到店主要聊供货和推广，别把"没评分"当缺点」；招牌菜空 → **橙色 ＋ 可录入**。
- **榜单信息**（2026-09-13 新增）：**两处都显示** —— ① 卡内**一行**（金色）：`榜单  东站美食热门榜 · 第1名`；② 店名卡「品类」那一行的**右侧**（金色小字，正好有空间）。没值就不出。
- `连锁情况` 一项（2026-09-13 定）：**单店不显示** —— 只有真连锁（平台 `连锁店数量` ≥1）才出这一行；单店是绝大多数，写出来只是噪音。

### 4. 🛎 服务与设施（含 📍 商圈与位置）

- 团购 / 外卖：两个**可点改**的大标签（未开 ⇄ 已开，点了弹页内确认框）。
- **设施区**（2026-09-13 定）：`特色服务` / `服务设施` / `配套设施` **合并成一项** —— 小标题固定 **「配套·服务·设施」**，三类的标签（含业务员现场补录的）**全部放在一起显示**；**有值才显示**。平台的空格分隔值 → 拆成标签 chip。录入用 **「团购/外卖」大标签那一行最右边的小 ＋**（`.plusbar`）。
  - ⚠️ `配套设施` 列里混着 `收录4年` 这类**收录时间**（不是设施）→ **导入时滤掉**。
- 卡内下方分区 **📍 商圈与位置**：只剩 **地址**（商城档案，永远有）+ **商圈**（平台有才显示；没有 → 这一行不显示）+ **🗺 地图**。**「平台地址 / 平台图片 / 点评页」三行都不显示**（老板 2026-09-13 定，`platAddr`/`pics`/`url` 字段仍入库只是不展示）。
- 商圈**不做手工录入**（老板 2026-09-13）：平台没收录的字段我们不去补，以后导入平台数据自然就有。
- 标题右侧小胶囊：**团购 / 外卖 哪个「有」才显示哪个**，两个都没有 → 标题栏右侧什么都不显示（老板 2026-09-13 定）；小胶囊**只显示、不可点**（可点的是卡内的大标签）。
- **📍 商圈与位置 里还挂一块小地图**（老板 2026-09-13 定，待真机落地）：**不可拖动 + 可双指缩放 10~20 级 + 以客户坐标为中心 + 初始 16 级**，高 **150px（≈300rpx）**、圆角 12px。参数与两个真机坑见 §七 / `客户详情页-设计定稿.md` §3.9。⚠ 演示稿里有一块 **CSS 画的「示意地图」**（路网背景 + 中心 📍 + 右下 ＋/− + 右上「示意」角标）—— **只是为了先看占位大小与观感**；真机是微信 `<map>` 原生组件，各店周边路网不同，也没有那个角标。

### 5. 📝 管理员备注

- **可多条**，一条一行：**前面日期、后面内容**。
- 日期**不带年份**（`09-05` 而不是 `2026-09-05`），样式**朴素**：浅灰小字（`#A6AEBC` / 11px / 不加粗 / 无色块无边框），条与条之间一条淡灰细实线。
- 数据结构：`remarks: [{d:'09-05', t:'内容'}, …]`（**不是**单条 `remark` 字符串）。
- **空态**：淡灰空态「还没有备注」+ 小字「管理员在后台加备注，这里就能看到」。

### 6. 🕑 拜访历史

- 折叠区里是**一叠历史卡**：`状态胶囊 + 日期时间 · 拜访人 + 时长` / 拜访文字 / 样品。
- 拜访人跟「签约业务员」同一口径（客户表「业务负责人」原值）。
- **空态**：淡灰空态「暂无拜访记录」+ 小字「第一次上门后，这里会留下记录」。

| **不补录（整行不显示）** | 📍 商圈 | **什么都不显示**（不给 ＋，也不写「未标注」） | 平台没收录的不由我们补录，以后导入平台数据自然就有 |
| **客观数据缺失** | 🏪 商城信息 / 📦 订单 / 📊 评分 / 📝 备注 / 🕑 历史 | **淡灰空态**：虚线框 + 灰图标（45% 透明）+ 一句主文案 + 一行更小的提示 | 这些是系统/平台里的客观事实，业务员**录不了**；标 ＋ 号会误导 |

**空态文案表**（演示稿现行版；⚠️ 这几句是拟的，**老板可改**，见 §九）：

| 卡 | 小字 | 主文案 | 提示行 |

## 四、门店照片（门头照）

**取图口径（老板 2026-09-13 拍板）：平台图打底 + 业务员现场拍覆盖。**

- 挂在 **🏪 商城信息** 卡内的 `📷 门店照片` 分区（**不是独立卡**）。
- **三个相框**：有照片 → 显示照片（点了看大图）；空框 → 虚线框 + 📷 + 「拍照」，**点一下就地拍**。
- 平台图只取点评的 **`poipicadd` 域名**「店铺主图」；`bdb`＝平台"美食"占位图、`wmproduct`＝外卖菜品图 → **都排除**。
- 平台图是美团 CDN 外链 → **导入时转存到自己的云存储**（小程序 `<image>` 直接吃外链要面对防盗链/域名策略，别赌）。
- 现场拍的**优先级更高**（更清晰、更准），存进客户档案，全公司可见。
- **本批（金华-永康 463 家）没有平台图** → 三格全空，等业务员现场拍；以后导入杭州等有图的批次（约 26% 有真门头照）自动填第一格。
- 因为「商城信息」卡永远在，**未入商城的客户也有三格**（原来"没拍照入口"的问题已解决）。

## 八、数据来源（详见 `_scratch/客户数据导入规范.md`）

| 内容 | 来源 |
|---|---|
| 客户名 / 地址 / 电话 / 联系人 | 商城客户表（**签约业务员**取「业务负责人」列原值） |
| 商城注册 / 最近下单 / 最近浏览 | 商城导出 |
| 平台口碑 / 商圈 / 招牌菜 | 大众点评抓取（`plat.*`） |
| 特色服务 / 服务设施 / 配套设施 | 点评表同名列（**空格分隔标签串**）→ 设施区；**配套设施里的「收录N年」导入时滤掉** |
| 榜单信息 | 点评表·榜单信息（形如 `东站美食热门榜 · 第1名`）→ **只放口碑卡的卡内一行** |
| 大中小类 | 点评表·大类/中类/小类 → 店名卡品类行（去重后拼） |
| 连锁店数量 | 点评表·已登记的连锁店数量 → 口碑卡「连锁情况」；**为 0（单店）时不显示这一项** |
| 外国 | 点评表·外国（布尔）—— **本批全 False，暂不展示**（字段仍入库） |
| 门头照 | 点评「店铺主图」（`poipicadd`，转存云存储）+ 业务员现场拍 |
| 订单 / 订单明细 | 销售订单表 + 每单明细文件 |
| 管理员备注 | 后台录入（`remarks[]`） |
| 拜访历史 | 拜访记录（`visits`） |

**入库原则**：一套 `customers` 集合装全部客户（不搞旁路表）；源表每一列都要有归处（**不聚合、信息全进**）；同一个客户编号 = 同一家店（老板/老板娘各自注册）→ 购买次数多者为主、副家订单全要。
