# 自由拜访 · 方案与口径（定稿 v2）

> 2026-10-03 与老板逐条确认后整理（v2：补完地图页细节、计数口径、单开限制等）。
> **本文档只定方案，尚未写代码。**
> 老板原话开头：「我想把业务员首页的『团队』功能改成『自由拜访』…」

---

## 〇、一句话说清这是什么

**给业务员一个"自己找店去跑"的工具**：打开地图，看到自己附近的客户点，
挑一家导航过去拜访；这一趟跑过的店，收进一张**「自由拜访卡」**里。
老板在后台能看到每个人跑了哪些店。

**和现有「正式任务」的根本区别**：

| | 现有正式任务 | **自由拜访** |
|---|---|---|
| 谁建的 | 老板在后台派单 | **业务员自己在手机上建** |
| 目标客户名单 | 有（一批客户） | **没有** |
| 进度怎么算 | 已拜访 ÷ 指派总数（%） | **没有分母** |
| 截止日 / 自动归档 | 有 | **没有** |
| 任务编号 | 有（`JH05-xxxxxxx`） | **不需要** |
| 拜访中单开 | 同一任务同时只允许 1 家 | ⭐ **不受限制** |
| 数据落点 | `tasks` 集合 | ⭐ **独立集合** `free_trips` |

## 一、口径定稿（老板逐条确认，勿翻案）

### 1) 手机端入口

| 项 | 结论 |
|---|---|
| 入口 | 首页快捷卡「👥 **团队**」→ 改成「🚶 **自由拜访**」 |
| ⚠️ 背景 | 「团队」那张卡**本来就是空占位**（首页四个快捷卡：业绩/团队/记事/新店，只有「记事」「新店」落地了），直接换，零负担 |

### 2) 自由拜访卡片页

| 项 | 结论 |
|---|---|
| 内容 | 列出**该业务员自己**的自由拜访卡 |
| 卡片显示 | **区域 · 商圈**（取**建卡时的中心点**）· 建卡时间 · **已拜访 N 家** · 业务员 |
| ⭐ 计数口径 | ⚠️ **2026-10-03 老板改口径：按「家数」** —— **同一家被拜访 2 次 3 次都只算 1 家**（去重）；取消拜访不计数。⚠️ 原「按次数」的口径**已作废** |
| 点进去 | **客户卡片** = 这趟**去过的店**（⚠️ 按**去重**列，同一家只出现一次） |
| ⭐ 底部按钮 | **「🗺 继续跑店（回到地图）」** —— ⚠️ 2026-10-03 老板指出：进「已拜访的店」后**必须能一步回地图**，否则要退两步才能接着跑 |
| 底部 | 「🗺 **打开地图**」（与「加新店」页的按钮风格一致） |
| 生命周期 | 能**结束**，也能**再次唤醒** —— ⭐ 可重复用（"结束"= 暂时收工，不是作废） |

### 3) 地图页

| 项 | 结论 |
|---|---|
| 中心 | **我的当前定位** |
| 范围档位 | **200m / 500m / 1km / 2km**，**默认 500m** |
| 圆圈 | ⭐ 用 `<map>` **原生 `circles`** 画橙圈（不自绘） |
| 客户点 | 范围内的**所有客户点**（markers） |
| 我的位置 | **蓝色定位点**，**始终实时更新** |
| 「🔄 刷新」 | **唯一**的取点方式（**不自动跟随走动**） |
| 切档位 | ✅ **自动拉一次 + 视野自动充满整圈**（⭐ 2026-10-03 老板定：选 200m/1km/2km 后圈正好铺满屏幕，不用再按右上角 ⛶）|
| 「📌 固定范围」 | 圈心 + 客户点**锁死**，**刷新禁用**、⚠️ **档位也一起锁死**；⚠️ 要**二次确认** |
| 「📍 解除固定」 | ✅ **允许解除**（老板后改的口径）→ 圈心回到我的定位 + 自动拉一次 + 档位解锁 |
| 「➕ 建立自由任务」 | 生成一张自由拜访卡；⚠️ **建完留在地图页**，只提示「已建立，去卡片页看看」 |
| **点一家客户** | ✅ **先弹小卡**（店名 + 地址 + 【导航】【看详情】【去拜访】）—— 不是直接导航 |
| **已拜访过的店** | ✅ 在地图上**区别显示**（灰针），免得跑重复 |
| ⭐ **出圈了还显示吗** | ⭐ **显示**（2026-10-03 老板定）—— 拉点时**额外把「这张卡去过的店」也一起画上**，不管在不在圈内、甚至在别的商圈；⚠️ **但视野不跟着它们跑**（地图仍按圈显示，圈外的灰针在视野外不碍事，拖过去/缩小才看到）。否则跑一天跨三个商圈会把地图拉得很小、圈都看不清 |
| 出圈提醒 | ⚠️ **震动 2~3 下** + 提示条（见 §二），⚠️ 必须去重否则会"一直震" |

### 4) 拜访归属与单开

| 项 | 结论 |
|---|---|
| 归属 | **自动记入最新建的那张卡** |
| 多张卡 | ✅ **允许同时多张"在用"**，拜访只进**最新**那张 |
| 没有卡就拜访 | ✅ **允许**（记为"无任务拜访"，`visits` 已支持 `taskId` 为空） |
| ⭐ **拜访中单开** | ✅ **自由拜访不受限制**（可同时开多家）；⚠️ **正式任务内部"只 1 家"的限制不变** |
| ⚠️ 更精确地说 | 自由拜访**完全不参与**单开拦截 —— 他任务里正有 1 家在拜访中，也照样能开自由拜访 |
| 建卡**之前**的拜访 | ⚠️ **不算**进新卡（新卡只收"建卡之后"的拜访） |

### 5) 统计

| 项 | 结论 |
|---|---|
| 进不进统计 | ✅ **进**（跟"无任务拜访"一致：进拜访历史、进统计） |
| 进不进任务进度 | ❌ **不进**（不绑任务，没有进度分母） |
| ⚠️ 取消拜访 | **不计数**（卡片数字不涨；客户卡片里也不留） |

### 6) 后台

| 项 | 结论 |
|---|---|
| 入口 | ⭐ **「任务管理」里的第三个 Tab**（与现有「当前 / 历史」并列） |
| 筛选 | 选**业务员**，或「**全部**」 |
| 内容 | 各业务员创建的自由拜访卡片 |
| 能力 | **能看、能删**（⚠️ **只读 + 删除**，不给改） |
| ⚠️ 删卡的影响 | 只删"归类"，**拜访记录本身不删**（`visits` 是独立集合） |

## 二、地图页的状态机（本次最核心的设计）

| | **① 跟随态（默认）** | **② 固定态（点了 📌）** |
|---|---|---|
| 圈的中心 | 跟着**我的定位**走 | **锁死**在按下那一刻 |
| 客户点 | 上次拉的那批 | **锁死** |
| 「🔄 刷新」 | ✅ 可用 | ❌ **禁用** |
| **范围档位** | ✅ 可切（切了自动拉） | ❌ **也锁死**（老板定） |
| 「📌/📍」 | 「📌 固定范围」 | 「📍 解除固定」 |
| 「我的蓝点」 | ✅ 实时更新 | ✅ **仍然实时更新**（老板要求："人的蓝色点位可以在这个范围里面自由移动"） |

**为什么"固定后禁刷 + 锁档位"是对的**：中心不动 ⇒ 再拉还是同一批点。如果允许切档位，会出现"**圈变了、点没变**"的怪状态。禁掉不是限制，是省得业务员白点。

### 蓝点走出圈怎么办

⚠️ **2026-10-03 老板定：要震动几下提醒**（原稿写"不弹窗、不震动"，**已作废**）。

- **只在"固定态"下可能发生**（跟随态圈心就是我的位置，不存在出圈）
- **表现**：提示条写「⚠️ 你已在范围外」+ **震动 2~3 下**
  - 用 `wx.vibrateShort({ type: 'medium' })`，连调 2~3 次、间隔约 200ms
- ⚠️⚠️ **必须去重，否则会"一直震"**：蓝点在圈边来回晃时，若每帧都判"在圈外"就会疯狂震动。
  - **只在"圈内 → 出圈"这一次跳变**时震；**持续待在圈外不重复震**
  - 回到圈内后**再出圈**，才再震一次
  - 另加**冷却**（如 60 秒内不重复），防他在边界反复横跳被连环震
- 实现：存实例变量（如 `_wasOut`）记住上次是否在圈外，**只有 false→true 才触发**

### 省电/省流量的账

| 动作 | 网络 |
|---|---|
| 打开地图 | 拉**一次** |
| 走路 | **不拉**！只更新蓝点（本地定位，不走网络） |
| 切档位 | 拉一次 |
| 点「🔄 刷新」 | 拉一次 |
| 固定后 | **再也不拉** |

👉 跑一趟下来网络请求**可能就几次**，比"实时跟着走"省太多，手机也不烫。

## 三、数据模型

### 独立集合 `free_trips`（自由拜访卡）

```js
{
  _id,
  salesmanId, salesmanName,        // 归属业务员
  centerLat, centerLng,            // ⭐ 建卡时的中心点（卡片上的区域/商圈由它反查）
  district, bizCircle,             // 中心点所属区域 / 商圈（卡片显示用）
  radius,                          // 建卡时选的档位（200/500/1000/2000）
  customerIds: [],                 // ⭐ **去重的客户 id** —— 它同时是三个东西的数据源：①卡上"已拜访 N 家"= 数组长度 ②"点进去看客户卡片"的列表 ③地图上"灰针(去过)"的判断（都不用另外查库）
  status,                          // 'active'（在用）| 'paused'（已结束，可唤醒）
  createdAt, updatedAt,
  pausedAt,                        // 结束时间（可空）
  createdByName
}
```

⚠️⚠️ **卡上那个"已拜访 N 家"就是  的数组长度**（2026-10-03 老板改口径：**按家数、同一家跑几次都只算 1 家**）：
```
N = count( **去重后的** customerId，条件：visits where freeTripId == 这张卡._id and 拜访成功 )
```
理由（老板口径："**按家数去重**，同一家去两次算 1，取消不计"）：
- 存"计数"字段的话，**取消拜访**时还得回头减、容易不一致
- 由 `visits` 现算，**永远跟真实拜访记录一致**（取消=记录被删 ⇒ 自然不计数）

⚠️ 而 `customerIds` 是**去重**的 —— 维护方式：**拜访成功**时把 customerId push 进去（**已存在就不重复加**）；**取消拜访**时，若这家在本卡没有别的成功拜访了，就把它**摘掉**（所以"取消不计数"自动成立）。

### `visits` 加一个字段

```js
freeTripId: ''      // 归属的自由拜访卡；没有就为空（= 无任务拜访）
```

⚠️ 现有 `taskId: ''` 的"无任务拜访"逻辑（已做）**保持不变**，只多一个归属标记。

### 为什么用**独立集合**而不是塞进 `tasks`（老板拍板）

自由拜访**不绑客户、不算进度、不参与派单、没有截止日**，跟 `tasks` 表结构几乎不重叠。
硬塞进去要在**进度计算 / 截止日 / 自动归档 / 后台列表 / 老板看板 / 战况统计**……一处一处加"排除自由任务"的判断，**改十处、漏一处就是"老板看到进度不对"**。独立集合是纯新增，碰不到现有任务一根汗毛。

## 七、已知取舍与风险（先说清楚，免得后面当成 bug）

| # | 事项 | 说明 |
|---|---|---|
| 1 | **2 公里那档点很多** | 参考：金东区万达 **200 米内就有 81 家**。默认给 500 米就是这个原因 |
| 2 | **固定后看不到新店** | 固定期间别人在附近新建/新导入的店，**不会**出现在圈里（刷新与档位都锁了）。老板明确要的取舍 |
| 3 | ⚠️ **小程序一个页面只能放一个 `<map>`** | 项目既有铁律，本页只放一个 |
| 4 | ⚠️ **圆圈用原生 `circles`** | 别改成自绘/叠层 —— 原生组件层级问题项目里踩过 |
| 5 | **自由拜访不参与任务进度** | 后台任务进度分母**不含**它，这是设计不是漏算 |
| 6 | ⚠️ **删自由拜访卡** | 只删"归类"，**拜访记录不删** —— 与"客户回收站=软删"同一思路 |
| 7 | **同一家跑多次只算一家** | ⚠️ 2026-10-03 老板改口径：卡上「已拜访 N **家**」**按家数去重**（一家跑 2 次还是 1）；客户卡片同样是去重列表 —— 两者口径一致 |
| 8 | **建卡前的拜访不进卡** | 新卡只收"建卡之后"的拜访 |

| 已有功能 | 与"自由拜访"的关系 |
